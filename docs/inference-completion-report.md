## Finite boundaries and intentional dialect differences

PG-M covers canonical storage and the explicitly enumerated supported aliases.
SQ-M covers all 30 documented output/affinity cells, plus finite alias controls.
These narrow checks keep validation coupled to actual parameter and result
semantics. Native scenarios then check every distinct scalar, temporal, JSON,
numeric-safety, reference, and composite behavior. They do not repeat each SQL
alias through a second identical CRUD scenario.

PostgreSQL native UUID, network, MAC, numeric, money, and temporal storage can
change spelling. The expected native values are separately authored. SQLite
strings retain their exact spelling. PostgreSQL numeric preserves string output
or exact bigint output, while SQLite limits bigint to signed int64. PostgreSQL
Date and ISO strings share some storage types but retain different JavaScript
representations. SQLite Date/JSON text survives numeric affinities because these
serialized values are not numeric strings.

PostgreSQL `json` and `jsonb` share the structured mapper. Native `json` write,
select, and update returning are checked in OVERRIDE. JSON predicates use native
`jsonb` in KNOWN/COMP because PostgreSQL `json` has no equality operator. The
contract does not add an equality operator to that engine type.

Wrapper/reversal combinations run at analysis, validation, and type boundaries.
Native stored-null, consumed-null, defaults, and reference scenarios exercise the
distinct SQL behaviors. This is an explicit equivalence partition, not a claim
that every wrapper multiplied by every format and type spelling ran natively.

Counterpart files reviewed: `src/schemas/utils/analyzeSchema.ts`, both dialects'
`infer.ts`, `mapping.ts`, `normalize.ts`, and `lowerDesiredSchema.ts`, plus
`src/query/mapping.ts`, `src/types/views.ts`, both Schema/DesiredSchema/Mapping
unit suites, both native adapters, and their shared scenarios. Storage and
conversion remain dialect-owned. The only new adapter seam reads native catalog
types for shared acceptance assertions. No new production abstraction, dialect,
codec, schema support, or naming convention was introduced.
